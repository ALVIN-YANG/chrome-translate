# 构建与发布

日常安装使用 [Releases](https://github.com/ALVIN-YANG/chrome-translate/releases/latest) 的 `translate-chrome-*.zip`，不使用 GitHub 自动生成的源码 ZIP。项目尚未在 Chrome 插件市场发布。

## 生成安装包

需要 Node.js 22+。从干净提交执行：

```sh
npm ci
npm run check
npx playwright install --no-shell chromium
npm run test:browser
node scripts/package.mjs
```

已有浏览器回归证据、只需重新生成包时，可用 `npm run package` 运行 Node 检查及构建。它不替代浏览器验证。

输出为 `output/release/translate-chrome-<version>.zip` 和同名 `.zip.sha256`。包内根目录直接包含 `manifest.json`。打包只允许构建产物清单中的文件，不跟随符号链接；未知文件、缺失文件或版本不匹配会失败。ZIP 使用固定条目顺序、时间与压缩参数；相同构建文件生成相同字节，不包含本机路径。

校验下载文件：

```sh
# macOS（在安装包所在目录）
shasum -a 256 -c translate-chrome-<version>.zip.sha256
# Linux
sha256sum -c translate-chrome-<version>.zip.sha256
```

Windows 可用 PowerShell `Get-FileHash -Algorithm SHA256 <文件名>` 对照摘要。摘要可发现下载损坏或文件差异；它不是独立的发布者签名。

构建会先清理 `dist/`。`package.json` 和 `public/manifest.json` 的版本必须相同。运行时依赖许可证汇总在 `THIRD_PARTY_LICENSES.txt`；项目 MIT 许可证保存在包内 `LICENSE`。两份许可证文件都是必需产物。

## 发布前检查

1. 更新版本、验证记录和面向用户的发布说明。说明功能变化、兼容性与尚未验证的服务，不能把受控响应称为真实账号验证。
2. 运行上面的检查，在隔离配置里加载**准备发布的包**，检查安装、翻译、配置和关闭恢复；不要清空用户的日常浏览器配置。
3. 确认默认分支的 Node 22/24 与 Chromium CI 全部通过，确认包不含凭据、私人文本、调试文件及源码映射。
4. 推送已验证提交，以完整提交 SHA 创建对应 tag/Release，再上传 ZIP 和摘要。先检查远端是否已存在同一版本，不覆盖已发布资产；需要修正时发布新版本。
5. 从公开下载地址重新下载 ZIP，核对摘要及解压目录，确认 Release 指向实际验证过的提交。记录用户安装验收与自动测试的区别。

CI 的 `translate-chrome-ci` artifact 包含当前提交的 ZIP 和摘要，`browser-evidence` 包含受控浏览器结果、截图和失败 trace；它们保留 7 天。Artifact 是开发验证产物，日常用户仍使用 Release。
